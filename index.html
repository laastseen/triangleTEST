ИСТОЧНИК ОЖИДАЕМОГО РЕЗУЛЬТАТА

Спецификация треугольника

Программа принимает длины A, B, C и возвращает один из пяти результатов.

  1. Формат. Целая часть обязательна. Только цифры 0–9, необязательная точка или запятая и от 1 до 18 дробных цифр. Пробелы по краям и ведущие нули допустимы. Знаки +/−, экспонента, пробелы внутри, буквы, пустое поле, NaN, Infinity и HTML недопустимы.
  2. Диапазон. Каждая сторона строго больше 0 и не больше 1 000 000 000. Минимальное положительное значение — 0,000000000000000001. До 128 символов в поле, включая пробелы.
  3. Существование. A + B > C, A + C > B, B + C > A. При равенстве треугольник не существует. Неверный ввод проверяется раньше геометрии.
  4. Тип. Три равные стороны — равносторонний; ровно две — равнобедренный; все разные — разносторонний. Тип по углам не определяется.
  5. Точность. Десятичные значения сравниваются точно в указанном диапазоне, без округления и допуска. Перестановка сторон не меняет ответ.

Как работать на занятии

Выбери сборку → придумай проверку → укажи ожидание → сравни результат. Баг засчитывается, если твоё ожидание совпало со спецификацией, а результат сборки — нет. При неверном ожидании сначала пересмотри тест. Эталонная сборка доступна для самопроверки.

Что проверять дополнительно

Перестановки одинаковых данных, повторные запуски, замену одного поля, работу клавишей Enter и Tab, мобильный экран, длинный ввод, обновление страницы и сохранение прогресса. Умножение всех сторон на одно положительное число должно сохранять тип, если новые длины остаются в допустимом диапазоне и точности.

Как оформить баг-репорт

Заголовок → номер сборки → входные данные → шаги → ожидаемый результат → фактический результат. В найденных дефектах сохраняется первый воспроизводящий пример; журнал можно выгрузить в CSV.

Вдохновлено задачей LearnQA. Это самостоятельный учебный тренажёр; его дефекты и спецификация не воспроизводят оригинал буквально. Ответы видны в исходном коде: режим разбора не является защитой от списывания.
